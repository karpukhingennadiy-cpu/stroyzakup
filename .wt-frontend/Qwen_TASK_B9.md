# Задача для Qwen (Минитендер.рф / StroyZakup)

Привет! Помоги спроектировать задачу B9 из нашего плана разработки. Код будешь писать не ты — я (Hermes) вношу изменения сам. Твоя задача — **аналитика и проектное решение**, максимально конкретное, чтобы я мог сразу реализовать.

## Контекст

- Стек: Django 5 + DRF backend, Next.js 15 frontend.
- Заявка (Request) содержит позиции (RequestItem): material_type, quantity, unit, spec.
- RFQ-письма поставщикам сейчас — статичные шаблоны (RFQ_TEMPLATE_* в apps/emails/services.py).
- Входящие письма от поставщиков разбираются через process_inbound_email_reply.
- Есть образец LLM-сервиса с кэшем: apps/requests/services/material_intel.py.
- LLM провайдер — DeepSeek (openai-совместимый API).
- Deadline у КП: ссылка /quote/{token} живёт 3 дня (только что внедрено).

## Что нужно спроектировать

Промт-библиотеку  + сервис  для автогенерации деловой переписки с поставщиками. Сценарии:

1. Приглашение в тендер (RFQ) — персонализированный текст под поставщика и заявку.
2. Напоминание о дедлайне (за 24ч и за 2ч до срока).
3. Уточняющий вопрос поставщику (неясная цена/аналог/условия в его КП).
4. Ответ на вопрос поставщика по условиям заявки (только из данных заявки!).
5. Благодарность за КП + подтверждение получения.
6. Уведомление о победе / вежливый отказ остальным.

## Жёсткие правила безопасности промтов (в system-промте)

- Не обещать цены, скидки и объёмы от имени заказчика.
- Не выдумывать условия — только факты из заявки (позиции, адрес, срок).
- Тон: деловой русский, коротко, без канцелярита.
- Подпись «команда Минитендер.рф», без имён людей.
- Любые обещания/контрагентские формулировки → needs_review=true, письмо НЕ отправляется.

## Что мне нужно от тебя

1. **Схема JSON-ответа LLM** — единая для всех сценариев: {subject, body_text, body_html, needs_review}. С примером валидного JSON для каждого сценария.
2. **Структура system-промта** — точный текст (можно на русском), включая правила безопасности.
3. **Ключевые данные из модели Request/Supplier**, которые должны подставляться в промт (поля).
4. **Подводные камни** — что может пойти не так (галлюцинации цен, отказ от ответственности, инъекции через spec позиций) и как это ловить (валидация, фильтры).
5. Примеры для eval-набора: 2 провокационных входа (например «дай скидку 30% и мы подпишем») и ожидаемое поведение.

Отвечай структурированно, по-русски, без лишней воды. Это проектное решение — его реализует другой агент, поэтому пиши так, чтобы можно было сразу писать код по твоему ответу.
